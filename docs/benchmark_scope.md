# AgingVisBench 项目范围说明

> **公开范围：** 本仓库公开代码、方法和聚合结果；私有语料与行级分析数据不公开。V0.5 是历史研究快照，不是当前模型排行榜。

## 1. 项目一句话定义

**AgingVisBench** 是一个面向文生图模型的老龄化视觉偏见评测基准，采用“自动化测量 + 人工可靠性复核 + 现实证据校准 + 积极老龄化理论审查 + 规则化裁决”的混合方法，评估模型在生成老年人图像时是否呈现稳定的表征差异、刻板化风险或偏见风险。

英文辅助定义：

> AgingVisBench is a multi-evidence calibrated benchmark for auditing aging-related visual bias in text-to-image models.

## 2. V0.5 的目标

AgingVisBench V0.5 的目标不是建立正式排行榜，而是形成一个适合研究展示和实习作品集的可复现评测原型。

V0.5 需要做到：

1. 明确评测对象和问题；
2. 将论文变量整理为 benchmark 指标；
3. 说明自动化测量管线；
4. 人工复核样本报告自动测量可靠性；
5. 将现实证据和积极老龄化理论纳入解释；
6. 用裁决手册区分“差异”“刻板化风险”和“偏见风险”；
7. 输出跨模型风险矩阵和模型风险画像。

## 3. V0.5 不追求什么

V0.5 暂不追求：

- 单一偏见总分；
- 模型 leaderboard；
- 完整重新采样全部模型版本；
- 多名裁决者一致性验证；
- 长期在线 dashboard；
- 对全部图像进行人工标注；
- 证明某个模型整体“有偏见”或“无偏见”。

这些可以作为 V1.0 或后续项目拓展。

## 4. 核心评测原则

### 4.1 显著差异不等于偏见

统计显著差异只能说明模型在某一视觉指标上呈现稳定群体差异。是否构成刻板化或偏见风险，需要结合：

- 差异方向；
- 效应量；
- 跨模型稳定性；
- 现实证据；
- 积极老龄化理论；
- 自动测量可靠性；
- 可能的反向解释。

### 4.2 现实差异不能机械转化为偏见分数

现实世界中不同年龄群体可能确实存在健康、居住、社会参与、数字使用等方面差异。模型图像中的差异如果与现实证据部分一致，不能直接判定为偏见。

但如果模型显著放大某类差异，或将老年人持续表现为低主体性、低参与、被照护、被排除于现代生活之外，则可能进入刻板化或偏见风险讨论。

### 4.3 理论证据用于判断表征方向

积极老龄化理论不是用来描述现实人口分布，而是用于审查模型表征是否持续削弱老年人的：

- 主体性；
- 社会参与；
- 学习与发展；
- 数字融入；
- 社会连接；
- 多样化生活可能性。

### 4.4 跨模型稳定性提升风险判断强度

如果某一差异只在单一模型中出现，应优先视为模型特异性模式。若差异在多个模型中方向一致，且具有潜在负面含义，则更可能构成跨模型刻板化风险。

### 4.5 证据不足时降低结论强度

当现实证据缺失、人工复核一致性较低、模型间方向不一致或理论解释存在争议时，应使用“证据不足”或较低证据置信度，而不是强行做偏见判断。

## 5. 评测对象

V0.5 覆盖四类文生图模型或生成系统：

- ChatGPT / GPT image model；
- Midjourney；
- 即梦；
- 通义。

模型名称可以公开，但输出应避免简单排名。更合适的表达是：

> 不同模型在不同行为、场景和符号维度上呈现不同的老龄视觉风险画像。

## 6. 分析单位

AgingVisBench 的基本分析单位是单张生成图像及其关联元数据。

每张图像应尽量关联：

- 模型名称；
- 模型版本或生成批次；
- 年龄条件；
- 性别条件；
- 国籍条件；
- prompt 或 prompt 模板；
- 文件名；
- 图像路径；
- 自动评测结果；
- 人工复核结果，如适用。

## 7. 核心输出

V0.5 的核心输出包括：

```text

README.md

```



## 8. V0.5 成功标准

V0.5 完成时，应满足：

- 外部读者能在 5 分钟内理解项目评测什么；
- 指标、证据和裁决规则有明确文档；
- 可靠性复核不是隐藏在数据文件中，而是形成报告；
- 风险矩阵能直观看出四个模型的差异；
- README 能指导别人运行 dry-run；
- GitHub 仓库不包含 API key、私有图像或完整生成数据。
